# 「开始阅读」按钮位置设计（design_start_read）

> 范围：确认「开始阅读」按钮的归属区域，保证区域划分清晰
> 涉及文件：`index.html`、`assets/css/book.css`、`docs/spec.md`
> 约束：品牌基线 Navy(#1e3a5f) + Gold(#b8860b) 不变；改 CSS 需升级 `?v=` 破缓存
> 日期：2026-09-09（初版）/ 2026-09-09（回退修订）

---

## 1. 背景与决策

### 1.1 用户诉求

「开始阅读」按钮在区域划分上要清晰：

- 要和**书封面图标、书名、介绍文字**在一起，构成一个完整的「书籍展示区」；
- **不要**和「作者介绍」那部分整合到一起，避免按钮归属歧义。

### 1.2 最终决策

**复用英雄区已有「开始阅读」按钮，不在作者卡片新增 CTA。**

英雄区（页面顶部，index.html L81-102）本身即由「书封面 + 书名 + 英文副标题 + 介绍文字 + 开始阅读按钮 + 作者介绍按钮 + 续读提示」构成，天然满足「和书图标、书名、文字在一起」的要求，且与作者介绍区在视觉上各自独立、边界清晰。因此无需新增任何区域。

### 1.3 回退的改动

初版曾在作者卡片底部（联系方式之后）新增「开始阅读」CTA 作为收尾行动入口。该方案使按钮落入作者介绍区，与上述区域划分要求冲突，故回退：

| 文件 | 回退内容 |
|---|---|
| `index.html` | 删除作者卡片底部 `border-t` CTA 区块（按钮 + 续读提示 + 副文案） |
| `assets/css/book.css` | 删除 `.btn-cta` 修饰类及其深色模式规则 |
| `docs/spec.md` | FR1.7 改为「复用英雄区已有按钮，不在作者卡片重复设置 CTA」 |

---

## 2. 英雄区按钮现状（复用对象）

位置：`index.html` 英雄区 `<section>` 内，与书封面、书名、介绍文字同区。

```
英雄区 section（max-w-6xl grid md:grid-cols-2）
├── 书封面 cover.png
└── 文本列
    ├── 眉标 SILICON VALLEY · 回国决策手册
    ├── 书名《要不要回国？》
    ├── 英文副标题 Should I Go Back to China?
    ├── 介绍文字（40 章 · 约 14 万字 · 九大板块）
    ├── [📖 开始阅读]  ← 复用此按钮（btn-primary）
    ├── [作者介绍]      ← 跳转作者介绍区
    └── 续读提示（x-show="lastChapter"）
```

按钮行为：`@click="openChapter(lastChapter || '01')"`——有阅读记录续读上次章节，否则跳转第 01 章。与 `FR6.2` 一致。

顶栏另有一处「开始阅读」按钮（`hidden md:inline-block`，桌面端常驻），行为相同，构成「常驻入口 + 英雄区主入口」的双触点，本次不动。

## 3. 区域划分说明

| 区域 | 内容 | 是否含「开始阅读」 |
|---|---|---|
| 英雄区 | 书封面 + 书名 + 文字 + 开始阅读 + 作者介绍 | 是（主入口） |
| 核心理念 | 五因子模型主张 | 否 |
| 目录导航 | 9 篇 × 40 章跳转 | 否（点击章节即开始阅读） |
| 作者介绍 | 姓名 / 头衔 / 统计 / 简介 / 另著 / 联系方式 | **否**（回退后） |
| 页脚 | 书名 / 作者 / 金句 / 免责声明 | 否 |

「开始阅读」仅出现在英雄区（与书封面、书名、文字同区），作者介绍区不再重复设置，区域边界清晰、无归属歧义。

## 5. 验收标准

1. **作者卡片**：底部「联系作者」之后不再出现「开始阅读」按钮、续读提示、副文案，卡片以联系方式收尾
2. **英雄区**：书封面、书名、介绍文字、「开始阅读」按钮、「作者介绍」按钮、续读提示均保留且布局不变
3. **区域边界**：「开始阅读」仅存在于英雄区，与书封面/书名/文字同区，不与作者介绍区混在一起
4. **交互**：英雄区「开始阅读」点击跳转第 01 章（首次）或上次阅读章节（有记录时），行为不变
5. **样式**：`.btn-cta` 类已移除，页面无残留引用；btn-primary 视觉不变
6. **缓存**：book.css / app.js 引用均为 `?v=20260909-10`
7. **语法**：`node --check assets/js/app.js` 通过（本次未改 JS，确认无回归）
