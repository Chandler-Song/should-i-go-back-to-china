# 《要不要回国？》网页书 — 需求规格文档（spec.md）

> 版本：v1.0  
> 创建日期：2026-09-07  
> 输入：`gobackchina/` 40 章 markdown 原稿 + `docs/book_design_style.md` 设计风格  
> 约束：纯前端方案，零构建，CDN 引入

---

## 1. 项目背景

作者宋秀强已撰写《要不要回国？——硅谷工程师回国决策手册》一书，共 40 章、约 14 万字，原稿为 `gobackchina/` 下 40 个 markdown 文件。需将其网页化，做成一本可在线阅读的电子书，风格遵循 `book_design_style.md` 定义的"商务沉稳型社科图书网页风格"。

## 2. 目标读者

在海外（尤其硅谷）工作 5-15 年的资深工程师 / 管理者 / 管线专家，正在评估回国选项。需在桌面与移动端获得一致的优质长文阅读体验。

## 3. 功能需求

### FR1 首页展示

**FR1.1** 系统应提供首页，自上而下包含七个区块：英雄区、核心理念、五因子模型卡片、金句墙、目录导航、作者介绍、页脚。

**FR1.2** 英雄区应展示：书籍封面（SVG）、书名《要不要回国？》、英文副标题 "Should I Go Back to China?"、"开始阅读"按钮（跳转第 01 章）、"作者介绍"按钮（跳转作者介绍区块）。

**FR1.3** 核心理念区应以一段话讲清"回国 = 七子决策耦合序列 + 五因子决策模型"这一全书核心主张。

**FR1.4** 五因子模型卡片应展示 5 张卡片：动机、能力可迁移性、机会成本、家庭约束、时机，每张含因子名 + 一句话说明。

**FR1.5** 金句墙应展示 6-9 句从原稿精选的金句，卡片网格布局。

**FR1.6** 目录导航应按 9 个"篇"分组，每篇下展开所属章节，点击章节跳转阅读视图。

**FR1.7** 作者介绍应展示：作者姓名"宋秀强"、头衔标签（10年猎头 / 世界500强招聘经理 / GCDF职业规划师）、统计数字（5000+ 服务求职者 / 10+ 年从业 / 6+ 行业覆盖）、另著两部作品链接。「开始阅读」入口复用英雄区已有按钮（与书封面、书名、介绍文字同区），不在作者卡片内重复设置 CTA。

**FR1.8** 页脚应展示书名、作者、一句金句、免责声明摘要。

### FR2 章节阅读

**FR2.1** 系统应提供阅读视图，包含：顶部固定栏、阅读进度条、侧边目录、阅读区、底部翻页。

**FR2.2** 顶部固定栏应包含：返回首页按钮、当前章节标题、字号调节（A- / A+）、主题切换按钮。

**FR2.3** 阅读进度条应贴顶部显示，宽度随阅读区滚动百分比实时更新（0-100%）。

**FR2.4** 侧边目录应列出全部 40 章，按 9 篇分组，当前章节高亮，点击跳转。

**FR2.5** 阅读区应渲染当前章节 markdown 内容，最大宽度 720px 居中，正文衬线字体、行高 1.85、两端对齐。

**FR2.6** 底部应提供"上一章"和"下一章"按钮；第 01 章无上一章按钮（或禁用），第 40 章无下一章按钮（或禁用）。

**FR2.7** 章节内容应支持 markdown 全部常见元素：标题 h1-h3、段落、表格、引用块、有序/无序列表、代码、分隔线、加粗/斜体。

### FR3 章节加载

**FR3.1** 系统应按需加载章节：用户点击某章时，fetch 对应 markdown 文件并解析为 HTML 渲染。

**FR3.2** 系统应缓存已加载章节：再次打开已加载章节时，直接从缓存渲染，不重复 fetch。

**FR3.3** 系统应在当前章节渲染完成后，静默预加载下一章（仅缓存，不渲染）。

**FR3.4** 章节加载中应显示加载指示；加载失败应显示错误提示与返回首页链接。

### FR4 主题切换

**FR4.1** 系统应提供深色/浅色双主题切换。

**FR4.2** 主题选择应持久化到 localStorage，刷新后保持。

**FR4.3** 默认主题为浅色。

### FR5 字号调节

**FR5.1** 系统应提供正文字号调节，范围 16-22px。

**FR5.2** 字号选择应持久化到 localStorage，刷新后保持。

**FR5.3** 默认字号为 18px。

### FR6 阅读记忆

**FR6.1** 系统应将最后阅读的章节 id 持久化到 localStorage。

**FR6.2** 首页"开始阅读"按钮应跳转到最后阅读的章节（若有记忆），否则跳转第 01 章。

### FR7 路由

**FR7.1** 系统应使用 hash 路由：`#/` 为首页，`#/ch/{id}` 为对应章节。

**FR7.2** 系统应监听 `hashchange`，解析 hash 并切换视图。

**FR7.3** 直接访问 `index.html#/ch/25` 应直接打开第 25 章。

### FR8 响应式

**FR8.1** 桌面端（≥1024px）：侧边目录常驻左栏，阅读区居中。

**FR8.2** 平板端（≥768px）：首页卡片 2 列，英雄区双栏，侧边目录抽屉触发。

**FR8.3** 移动端（<768px）：全单列，抽屉目录（汉堡按钮 + 遮罩层），卡片堆叠。

### FR9 封面

**FR9.1** 系统应提供 SVG 自动生成的封面，包含：Navy 渐变背景、Gold 双线边框、书名、副标题、作者署名、装饰语。

**FR9.2** 封面应支持被同名 PNG 替换（`cover.png` 存在时优先使用）。

## 4. 非功能需求

### NFR1 性能

- 首页首屏渲染 < 1 秒（CDN 可达时）
- 章节首次加载 < 2 秒（含 fetch + parse）
- 缓存章节切换 < 100ms
- 预加载不阻塞当前章渲染

### NFR2 可用性

- 所有交互元素键盘可达
- Esc 关闭移动端抽屉
- ← → 翻章（阅读视图）
- 颜色对比度满足 WCAG AA

### NFR3 兼容性

- 现代浏览器：Chrome / Edge / Firefox / Safari 最近 2 年版本
- 不要求支持 IE

### NFR4 可维护性

- 章节元数据集中在 `chapters.js`，新增章节仅需追加一条
- 配色集中在 Tailwind config，换气质仅改色值
- 排版样式集中在 `book.css`

### NFR5 部署

- 纯静态文件，无需构建
- 推到 GitHub Pages 即用
- 必须经 HTTP 服务器访问（因 fetch 加载 markdown，file:// 不可用）

## 5. 内容需求

需为 40 章建立元数据，每章含：`id`（01-40）、`part`（1-9）、`file`（文件名）、`title`（章标题）。

| 2 | 薪酬与级别 | 09-12 |
| 3 | 城市与生活 | 13-17 |

| 5 | 信息收集与方法论 | 21-24 |

| 7 | 时机与案例 | 29-31 |

### CR3 金句

从原稿精选 6-9 句金句用于首页金句墙。

### CR4 作者信息

来源 `docs/author.md`：宋秀强，10年猎头，世界500强招聘经理，GCDF职业规划师，5000+ 服务求职者，10+ 年从业，6+ 行业覆盖，另著《职场上那些没人告诉你的》《关于求职，你要知道的那些事》。

## 6. 约束

- **纯前端**：不使用任何后端框架（用户偏好）
- **零构建**：不使用 Node/Vite/Webpack，CDN 引入
- **设计风格**：遵循 `book_design_style.md`
- **命名**：文件名英文 snake_case，目录英文（用户偏好）
- **语言**：界面与文档使用简体中文

## 7. 验收标准

1. 首页七区块完整渲染，配色字体符合设计风格
2. 40 章全部可加载、可渲染，markdown 元素正确显示
3. 深色/浅色切换正常，刷新保持
4. 字号 16-22 可调，刷新保持
5. 阅读进度条随滚动更新
6. 移动端抽屉目录正常
7. 翻页正确，首末章边界处理正确
8. 路由正确，直接访问 `#/ch/XX` 可打开对应章
9. 桌面/平板/移动三档响应式正确
10. 经 HTTP 服务器访问无控制台错误

## 8. 不做范围

- 不做全文搜索
- 不做评论/批注
- 不做 SSR/SEO
- 不做后端
- 不做构建工具
- 不做 PWA/离线
- 不做用户账号/登录
