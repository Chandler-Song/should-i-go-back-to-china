# 第 37 章　简历本土化改造

> 硅谷简历直接投国内几乎无效。本章讲如何把简历本土化，让国内 HR + hiring manager 读懂 + 想面试你。

---

## 37.1　硅谷简历 vs 国内简历的差异

### 长度

- 硅谷：1 页（资深最多 2 页）。
- 国内：2-3 页正常，资深可更多。**不要强行 1 页**。

### 格式

- 硅谷：简洁 + 动词开头 + 量化。
- 国内：信息更全（学历 + 工作日期 + 公司 + 职级 + 项目 + 技能 + 论文 / 专利）。

### 职级

- 硅谷：不写级别（或写 L6）。
- 国内：**写级别**（阿里 P7 / 字节 4-1），HR 按级别筛。

### 量化

- 硅谷：量化（X% 提升 / Y 用户）。
- 国内：同样量化，但**用国内熟悉单位**（亿级用户 / 万 QPS / 亿营收）。

### 语言

- 硅谷：英文。
- 国内：**中文**（外企 / 国际化岗可英文）。

### 项目

- 硅谷：项目 + 影响。
- 国内：项目 + 影响 + **技术栈 + 团队规模 + 你的角色**更详细。

## 37.2　本土化改造的八个要点

### 要点一：中文 + 国内格式

- 翻译成中文（技术术语可保留英文）。
- 国内格式：基本信息 + 教育 + 工作 + 项目 + 技能 + 论文 / 专利 + 其他。
- **不要直接翻译硅谷简历**，按国内格式重组。

### 要点二：写级别 + 对应

- 写硅谷级别 + 国内对应（"Google L6，对应阿里 P8 / 字节 5-1"）。
- HR 按级别筛，不写级别可能被误筛。

### 要点三：量化 + 国内单位

- 用国内熟悉单位：亿级用户 / 万 QPS / 亿营收 / PB 数据 / 万卡训练。
- 避免硅谷单位（MAU / DAU 国内也用但配合中文）。

### 要点四：公司 + 业务说明

- 硅谷公司国内可能不熟（startup / mid-size），加说明。
- 例："Stripe（全球领先支付 infra 公司）"。
- 大公司（Google / Meta / Apple）不需说明。

### 要点五：项目 + 技术栈 + 角色

- 每项目：业务背景 + 技术栈 + 团队规模 + 你的角色 + 影响。
- 国内 HR 重视技术栈 + 角色，不只看影响。

### 要点六：教育 + 论文 / 专利

- 教育：博士 / 硕士 / 本科 + 学校 + 专业 + GPA（如高）。
- 论文 / 专利：顶会 / 顶刊 + 专利，海归博士重要。
- 国内 HR 重视教育 + 论文。

### 要点七：技能 + 关键词

- 技能列表：编程 / 框架 / 系统 / 算法 / 工具。
- 加国内关键词（如"大模型训练 / 推理优化 / 分布式 / 高并发"）。
- HR 用关键词筛，加对关键词。

### 要点八：海归标识

- 明确"海归"身份 + 在美经验 + 可回国时间。
- 部分公司有海归偏好，标识有利。

## 37.4　一个本土化案例

### 硅谷版（原文）

```

Google L6 | Staff Engineer

Education
PhD, CS, MIT, 2015

Experience
Google | Staff Engineer | 2019-now
- Led LLM training infra, improved throughput 40%
- Architected distributed training system, 10x scale

Stripe | Senior Engineer | 2015-2019
- Built payment infra, $1B processed
```

### 国内版（本土化）

```
张三 | 138-xxxx-xxxx | john@x.com | LinkedIn | 2026 年 1 月可回国
海归 | Google L6 Staff Engineer | 对应阿里 P8 / 字节 5-1

## 教育背景
博士 | 麻省理工学院 | 计算机科学 | 2011-2015 | GPA 3.9

- 分布式训练系统架构（技术栈：GSPMD / Megatron）：我主导架构，扩展 10x 规模，万卡训练。

Stripe（全球领先支付 infra 公司）| 高级工程师 | 2015-2019

## 核心项目

## 技能
- 编程：Python / Go / C++ / Java
- 框架：JAX / PyTorch / Megatron / Ray
- 系统：分布式训练 / 高并发 / 大规模
- 算法：大模型训练 / 推理优化 / 并行
- 工具：GCP / AWS / TPU / GPU

## 论文 / 专利
- ICML / NeurIPS 大模型训练 5 篇
- 美国专利 3 项
```

**差异**：中文 + 国内格式 + 级别对应 + 量化国内单位 + 公司说明 + 技术栈 + 团队 + 角色 + 论文 + 海归标识。

## 37.5　简历的"针对性"

不要一份简历投所有，针对性改造：

### 按公司

- 字节：突出 AI / 推荐 / 大规模。
- 阿里：突出云 / infra / to B。
- 腾讯：突出社交 / 游戏 / WLB 适配。
- 华为：突出芯片 / 系统底层 / 自研。

### 按方向

- AI 算法：突出顶会 / 大模型 / 算法。
- infra：突出分布式 / 大规模 / 性能。
- 芯片：突出芯片设计 / EDA / 流片。
- 出海：突出国际化 / 跨文化 / 海外经验。

### 按级别

- P7 / 4-1：突出独立 + 系统 + 业务。
- P8 / 5-1：突出 tech lead + 跨团队 + 架构。
- P9 / 6-1：突出技术领导 + 影响 + 战略。

**建议**：准备 2-3 版（按公司 / 方向 / 级别），不一份投所有。

## 37.6　简历的"反 ATS"

国内部分公司用 ATS（申请人跟踪系统），简历需 ATS 友好：

- **关键词**：加目标岗位 JD 关键词（大模型 / 分布式 / 等）。
- **格式**：简单 + 无复杂排版 + 无图片（ATS 解析）。
- **文件**：PDF（格式保）。
- **命名**：姓名_目标岗位_级别.pdf。

## 37.7　简历的"反夸大"

国内简历文化允许适度包装，但不要夸大：

- **量化真实**：40% 提升是真的，不写 400%。
- **角色真实**：tech lead 是真的，不写架构师（如不是）。
- **项目真实**：你真做了，不写没做的。
- **背景调查**：国内背景调查趋严，夸大可能被发现 + offer 撤。

**建议**：适度包装（突出亮点）但不夸大（不编造）。

## 37.8　简历的 review

简历写完需 review：

- **朋友 / 前同事 review**：技术 + 经历准确性。
- **猎头 review**：HR 视角 + 关键词。
- **国内朋友 review**：本土化 + 格式 + 文化。
- **家属 review**（如配偶同行）：客观视角。

**建议**：至少 3 人 review，迭代 2-3 版。

## 37.9　简历之外的"求职材料"

### 求职信 / cover letter

- 国内不强制，但部分公司 / 猎头要。
- 简短：1 段说清你是谁 + 为什么这岗位。

### 推荐信

- 国内不强制，但海归博士 / 高校要。
- 硅谷前老板 / 同事写，英文可。

### 作品集 / GitHub

- 技术岗加 GitHub（开源 / 项目）。
- 算法岗加论文 / 顶会。

### LinkedIn

- 与简历一致 + 更详细。
- 国内部分 HR 看 LinkedIn。

## 37.10　一个完整简历改造流程

1. **写硅谷版**：英文 + 硅谷格式。
2. **翻译 + 重组**：中文 + 国内格式。
3. **加本土化要素**：级别对应 + 国内单位 + 公司说明 + 技术栈 + 海归标识。
4. **针对性**：按公司 / 方向 / 级别准备 2-3 版。
5. **review**：3+ 人 review，迭代。
6. **ATS 友好**：关键词 + 格式 + PDF。
7. **配套**：求职信 + LinkedIn + GitHub。
